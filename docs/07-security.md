# Review keamanan NotchUI

Tanggal: 2026-11-04. Metode: inspeksi manual statis terhadap seluruh source yang tersedia di `src/NotchUI`, self-check pengaturan, dan dokumen 01–06. Tidak ada perubahan kode keamanan yang diterapkan. Review ini bukan hasil eksekusi Codex Security scanner, audit dependensi daring, atau pengujian Windows.

## Hasil dan batas bukti

Tidak ditemukan vulnerability Critical/High yang dapat dibuktikan dari source yang tersedia. Aplikasi adalah utility lokal: tidak ada listener jaringan, server, WebView, eksekusi shell, input path pengguna, autentikasi, token, atau penyimpanan metadata media pada source yang diperiksa. Ini tidak berarti aplikasi sudah memperoleh persetujuan rilis keamanan. Review lanjutan pada tanggal yang sama mencakup bootstrap `App`, coordinator, UI XAML, project aplikasi, dan manifest MSIX yang baru ditambahkan.

Batas kepercayaan utama: JSON preferensi per pengguna masuk ke codec; metadata media berasal dari aplikasi lain melalui GSMTC; pesan Win32 masuk melalui HWND; callback native memanggil managed code. Proses desktop harus berjalan dengan hak pengguna biasa. MSIX dan LocalSettings bukan batas isolasi terhadap proses lain dengan akun Windows yang sama; data yang disimpan memang hanya preferensi nonrahasia.

## Temuan dan tindak lanjut

| SEC-01 | Low — hardening availability | `Interop/TrayIconHost.cs`, `WndProc`/`ShowMenu`; `Interop/OverlayWindowHost.cs`, `WndProc` | Action Settings/Exit dan event `SystemStateChanged` dipanggil dari callback native tanpa penanganan exception pada batas callback. Exception subscriber dapat menghentikan proses. Belum ada subscriber bootstrap yang tersedia untuk membuktikan jalur kegagalan nyata. Batasi panjang teks tampilan, gunakan kontrol teks biasa dengan trimming, dan pertimbangkan coalescing refresh jika stress test memperlihatkan beban. Temuan Low di atas adalah peluang hardening dengan dampak lokal yang terbatas, bukan vulnerability privilege/confidentiality yang terkonfirmasi. Pesan tray dapat dipalsukan oleh proses pengguna yang sama; Settings/Exit hanya menjalankan aksi lokal dengan hak yang sudah dimiliki. Jangan memperlakukan nomor pesan sebagai bukti identitas atau menambahkan aksi sensitif berbasis pesan tersebut.

Review integrasi: `OverlayWindow` menempatkan judul/artis langsung ke `TextBlock.Text` dengan `TextTrimming`, bukan parser markup; SEC-02 kini terbatas pada alokasi/event burst, bukan injeksi. Warna UI berasal dari snapshot Normalize sehingga substring/konversi tidak memproses string JSON mentah. Penyimpanan dilakukan langsung tiap perubahan; tidak ada debounce tertunda yang dapat menulis setelah Exit. Bootstrap belum menerapkan single-instance; beberapa proses dapat saling menimpa preferensi dan membuat beberapa overlay, tetapi tidak menembus batas akun/privilege. `Activate()` overlay awal berpotensi mengambil fokus dan merupakan isu UX, bukan privilege escalation. Constructor/startup tray belum mempunyai jalur cleanup/error UI; kegagalan startup perlu diuji sebagai masalah availability.

## Kontrol yang sudah terlihat pada source

- `SettingsCodec` membatasi input 4096 karakter, memakai `System.Text.Json` bertipe tetap tanpa polymorphic type loading, menolak versi/tipe salah, dan menormalisasi ukuran, nilai nonfinite, radius serta warna `#RRGGBB`. Parser JSON memiliki batas kedalaman default. Tidak ada path traversal atau deserialisasi objek arbitrer.
- `SettingsService` menyimpan snapshot dan backup preferensi saja, menangkap kegagalan storage, serta menjaga versi lebih baru dari overwrite setelah Load. Pesan error tidak membocorkan payload atau profil. Lock hanya berlaku pada satu instance service; single-instance bootstrap tetap diperlukan untuk konsistensi, bukan isolasi keamanan.
- Geometri overlay menolak nonfinite dan menjepit ukuran ke monitor. `SetWindowRgn` menyerahkan region kepada Windows saat sukses dan memanggil `DeleteObject` saat gagal. Penggantian region merupakan kepemilikan sistem. Region tidak dibebaskan lagi setelah transfer sukses.
- Menu tray memakai `finally` untuk `DestroyMenu`. Ikon dari `LoadIcon(NULL, IDI_APPLICATION)` adalah shared system icon dan tidak memerlukan `DestroyIcon`. Constructor gagal mencoba melepas subclass; Dispose tray idempoten.
- Battery hanya membaca status daya; clock hanya waktu lokal. Media memakai API sesi lokal, memeriksa kemampuan kontrol dan busy state, melepas event, serta memakai generation/version untuk mengabaikan hasil async lama. Stop media menghapus metadata dari state.
- P/Invoke memakai nama DLL sistem tetap, bukan input pengguna; tidak ada pointer arithmetic atau dereference pointer dari pesan eksternal. `lParam` hanya dibaca sebagai koordinat/angka pesan. Pembatasan pencarian DLL ke System32 dapat dipertimbangkan sebagai hardening eksplisit; tidak ada jalur DLL hijack yang dibuktikan di sini.

## Verifikasi wajib pada Windows sebelum rilis

1. Build/restore paket final sebagai pengguna standar; inspeksi manifest, daftar paket transitif, signature dan sertifikat MSIX. Pastikan installer tidak meminta elevasi yang tidak diperlukan.
2. Uji startup gagal, penutupan dashboard, Exit dari tray, Explorer restart, pengulangan buka/tutup Settings, dan sleep/resume. Pantau handle USER/GDI agar stabil serta pastikan tidak ada callback sesudah disposal.
3. Uji sudut transparan lintas proses dan geometri selama animasi; notch tidak boleh menutup input di luar area visual. Topmost tidak memberi hak untuk meniru prompt keamanan atau muncul di secure desktop.
4. Uji metadata panjang, Unicode/bidi, sesi media berganti selama await, event burst, akses media ditolak, dan toggle off selama request. Teks diperlakukan sebagai data; metadata tidak masuk log/storage.
5. Jalankan self-check codec; uji JSON rusak/terlalu besar/deep nesting/versi masa depan, storage gagal, dan pemulihan backup pada Windows. Self-check tidak membuktikan integrasi LocalSettings atau API native.

Status akhir review: seluruh source aplikasi yang tersedia, termasuk bootstrap/UI, coordinator dan konfigurasi paket, mendapat review statis. Tidak ada patch High/Critical yang diperlukan. Supply chain hasil restore, manifest executable/MSIX final dan perilaku native Windows masih memerlukan verifikasi. Tidak ada secret yang ditemukan dalam source/dokumen implementasi yang diperiksa; git history, file akun di luar scope, binary, dan arsip referensi tidak diaudit sebagai secret scan.
